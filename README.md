### Требования
Для запуска и разработки проекта вам понадобятся:

* **Python 3.14+** (проект использует современные возможности типизации)
* **Poetry** — инструмент для управления зависимостями и виртуальными окружениями.
* **Аннотация типов (Typing)**: Код полностью типизирован по современным стандартам:
  * Для аннотации ленивых генераторов используется класс `Iterator` из встроенной стандартной библиотеки `collections.abc` вместо устаревшего модуля `typing`:
    ```python
    from collections.abc import Iterator
    ```
  * Для коллекций применяются нативные типы данных в нижнем регистре (например, `list[dict]`), что исключает использование `typing.List` и `typing.Dict`.
  * Строгий линт**: Кодовая база успешно проходит проверку статическим анализатором типов `mypy` без предупреждений `[no-untyped-def]` (все функции, включая тестовые `pytest`, имеют явное указание возвращаемого типа `-> None` или `-> Iterator`).

### 1. Модуль `masks`
Модуль реализует две функции:
* Функцию маскировки номера банковской карты: get_mask_card_number.
Функция  принимает на вход номер карты и возвращает ее маску. Номер карты замаскирован и отображается в формате
    XXXX XX** **** XXXX, где X — это цифра номера. То есть видны первые 6 цифр и последние 4 цифры, остальные символы
    отображаются звездочками, номер разбит по блокам по 4 цифры, разделенным пробелами.

* Функцию маскировки номера банковского счета: get_mask_account.
Функция принимает на вход номер счета и возвращает его маску. Номер счета замаскирован и отображается в формате
    **XXXX, где X — это цифра номера. То есть видны только последние 4 цифры номера, а перед ними — две звездочки.

```python
from src.masks import get_mask_card_number, get_mask_account

# Пример вызова первой функции get_mask_card_number
result_1 = get_mask_card_number("7000792289606361")
# result_1 = "7000 79** **** 6361"

# Пример вызова второй функции get_mask_account
result_2 = get_mask_account("73654108430135874305")
# result_2 = "**4305"
```

### 2. Модуль `widget`
* Модуль содержит функции для работы с новыми возможностями приложения:
* Функцию маскировки номера банковской карты и счета: mask_account_card.
Функция обрабатывает информацию как о картах, так и о счетах. Принимает один аргумент — строку, содержащую тип
    и номер карты или счета. Возвращает строку с замаскированным номером.
Функция использует импорт следующих функций из модуля "masks":

Функция принимает на вход строку с датой в формате "2024-03-11T02:26:18.671407" и возвращает строку с датой

### 5. Модуль decorators (Декоратор логирования)

```python
from src.decorators import log

```

### 7. Модуль external_api
Функция принимает на вход путь до JSON-файла и возвращает список словарей с данными о финансовых транзакциях.
    Если файл пустой, содержит не список или не найден, функция возвращает пустой список. Файл с данными о финансовых
    транзациях operations.json находится в директорию data/ в корне проекта.
    Если JSON-файл пустой, содержит не-список или не найден, возвращается пустой список.
    Функция не проверяет считанный JSON-файл на правильность информации по всем транзакциям
    (наличие всех ключей и т.п.)

# Пример вызова первой функции rates_of_usd_eur_by_date

* **Работа с выходными:** Если дата выпадает на выходной или праздничный день (когда торги не проводились), функция автоматически ищет и возвращает курс за ближайший *предыдущий* рабочий день.
* **Ограничение:** Данные доступны для дат начиная с 1992 года.

**Пример использования:**

```python
from src.external_api import rates_of_usd_eur_by_date

# Пример 1: Запрос курса USD на рабочую дату
usd_rate = rates_of_usd_eur_by_date("2023-10-25T14:30:00.000000", "USD")
print(f"Курс USD: {usd_rate} руб.")  
# Выведет: Курс USD: 93.4574 руб.

# Пример 2: Запрос курса EUR на воскресенье (автоматически вернет курс за пятницу)
eur_rate = rates_of_usd_eur_by_date("2023-10-22T12:00:00.000000", "EUR")
print(f"Курс EUR (с учетом выходного): {eur_rate} руб.")
```

# Пример вызова второй функции conversion_of_transactions_to_rub

* **Рубли (RUB):** Возвращает сумму как есть.
* **Валюта (USD/EUR):** Автоматически запрашивает курс ЦБ РФ на дату операции и пересчитывает сумму.
* **Отказоустойчивость:** Если в валютной транзакции нет даты или API недоступно, функция возвращает `0.0`.

**Пример использования:**

```python
from src.external_api import conversion_of_transactions_to_rub

# 1. Пример рублевой транзакции (не требует запросов к API)
rub_transaction = {
    "date": "2023-10-25T14:30:00.000000",
    "operationAmount": {
        "amount": "5500.75",
        "currency": {"name": "руб.", "code": "RUB"}
    }
}

amount_rub = conversion_of_transactions_to_rub(rub_transaction)
print(f"Сумма: {amount_rub} руб.")  # Выведет: Сумма: 5500.75 руб.


# 2. Пример валютной транзакции (автоматически конвертируется по курсу ЦБ)
usd_transaction = {
    "date": "2023-10-25T14:30:00.000000",
    "operationAmount": {
        "amount": "100.00",
        "currency": {"name": "USD", "code": "USD"}
    }
}

amount_usd_to_rub = conversion_of_transactions_to_rub(usd_transaction)
print(f"Сумма в рублях: {amount_usd_to_rub} руб.")  # Выведет: Сумма в рублях: 9345.74 руб.
```
### 8. Модуль transaction_reader_in_csv_xlsx

Функция `transaction_reader_in_csv` считывает данные о финансовых транзакциях из CSV-файла с разделителем `;` и возвращает их в виде списка словарей.

#### 1. Подготовка CSV-файла
Создайте файл (например, `transactions.csv`) со следующей структурой:
```csv
id;date;amount;currency
1;2025-01-15;500.00;RUB
2;2025-01-16;1200.50;USD
```

#### 2. Пример вызова в Python
```python
from pathlib import Path
from src.transaction_reader_in_csv_xlsx import transaction_reader_in_csv

# Укажите путь к вашему CSV-файлу
file_path = Path("transactions.csv")

# Вызов функции
transactions = transaction_reader_in_csv(file_path)

# Вывод результата
print(transactions)
```

#### 3. Ожидаемый результат (Output)
```json
[
    {"id": "1", "date": "2025-01-15", "amount": "500.00", "currency": "RUB"},
    {"id": "2", "date": "2025-01-16", "amount": "1200.50", "currency": "USD"}
]
```

Функция `transaction_reader_in_xlsx` считывает данные из файлов Excel (`.xlsx`, `.xls`) и объединяет строки со всех листов в один список словарей.

```python
from pathlib import Path
from src.transaction_reader_in_csv_xlsx import transaction_reader_in_xlsx

# Укажите путь к файлу с транзакциями
file_path = Path("data/transactions.xlsx")

# Вызов функции
result = transaction_reader_in_xlsx(file_path)

# Обработка результата
if isinstance(result, list):
    print(f"Успешно прочитано транзакций: {len(result)}")
    # Пример вывода первой транзакции, если список не пуст
    if result:
        print("Первая запись:", result[0])
else:
    # Если функция вернула строку, то это описание ошибки
    print(f"Не удалось прочитать файл. {result}")
```

### Структура лог-файлов

Все логи сохраняются в корень проекта, в автоматически создаваемую директорию `logs/`:
* `logs/masks.log` — история маскировки номеров карт и банковских счетов.
* `logs/utils.log` — логи считывания и валидации входящих JSON-файлов с транзакциями.

### Используемые уровни важности
По умолчанию для всех модулей установлен уровень детализации **`DEBUG`**, что позволяет фиксировать полную цепочку событий:
1. `DEBUG` — техническая информация (какие данные выдал итератор, какой файл открывается).
2. `INFO` — подтверждение успешных операций (успешная маскировка, успешное чтение `list`).
3. `WARNING` — перехват некорректных пользовательских данных (неверная длина номера карты/счета, наличие букв в номере).
4. `ERROR` / `CRITICAL` — критические сбои программы (сломанный JSON, отсутствие файла на диске).

### Формат записи
Каждая строка лога стандартизирована и содержит следующие метаданные:
```text
[ГГГГ-ММ-ДД ЧЧ:ММ:СС] - [Имя_Функции.py] - [Уровень_Лога] - [Текст сообщения]
```

*Пример из `logs/masks.log`:*
```text
2026-06-10 14:05:11,813 - get_mask_card_number - INFO - убраны лишние пробелы
2026-06-10 14:05:11,814 - get_mask_card_number - ERROR - Ошибка - длина номера 123 карты не соответсвует 16 символам
2026-06-10 14:05:11,814 - get_mask_account - INFO - убраны лишние пробелы
2026-06-10 14:05:11,814 - get_mask_account - ERROR - Ошибка - длина номера  счета не соответсвует 20 символам
```

## Тестирование и покрытие (Coverage)

Проект управляется с помощью **Poetry**. Все тестовые модули изолированы друг от друга и проверяют конкретный функционал из папки `src`.

### Подготовка к тестированию
Перед запуском убедитесь, что установлены все зависимости и плагин для расчета покрытия (`pytest-cov`):
```bash
poetry install
```
*(Если плагин еще не добавлен в проект, установите его командой: `poetry add pytest-cov --group dev`)*

### Запуск тестов

* **Запуск всех тестов:**
  ```bash
  poetry run pytest
  ```
* **Помодульный запуск:**
  ```bash
  poetry run pytest test/test_mask.py
  poetry run pytest test/test_widget.py
  poetry run pytest test/test_processing.py
  poetry run pytest test/test_generators.py
  poetry run pytest tests/test_decorators.py
  poetry run pytest tests/test_utils.py
  poetry run pytest tests/test_external_api.py
  ```
* **Запуск тестов декоратора:**
```bash
  poetry run pytest tests/test_decorators.py
```
Для просмотра логов в консоли добавьте флаги `-s -k "console"`.*

### Анализ покрытия кода (Coverage)

Чтобы проверить, насколько хорошо тесты покрывают код в папке `src`, используйте следующие команды:

1. **Вывод отчета прямо в терминал:**
   ```bash
   poetry run pytest --cov=src
   ```

2. **Генерация подробного HTML-отчета:**
   ```bash
   poetry run pytest --cov=src --cov-report=html
   ```
   После выполнения команды в корне проекта появится папка `htmlcov/`. Откройте файл `htmlcov/index.html` в любом браузере, чтобы увидеть, какие строки кода остались не протестированы.

### Конфигурация тестов
Файл `test/conftest.py` содержит общие фикстуры для генерации данных, которые автоматически подтягиваются при расчете покрытия.
